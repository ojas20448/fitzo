# Fitzo 1.5.0 — shared AI permission

Source branch: `codex/release-1.5.0`. The owner authorized a GitHub push and new
Android/iOS builds, then selected a public store update on 2026-10-23.

## Changes

- One short Enable Fitzo AI disclosure, reused across features, with a single
  Profile switch. Existing saved choices are retained.
- Fitzo branding replaces the repeated Gemini badges. Paid API handling is
  described without promising zero retention or no human access.
- Text food estimates and already-open coach actions check shared permission.
  Preference write failures remain visible rather than reporting false success.
- Daily/weekly AI cron endpoints skip processing until server-verifiable
  account consent exists. Opted-in foreground reports remain available; scheduled
  AI report pushes pause once this backend revision is deployed.
- Android's previous builds 30 and 31 failed because six GIF/JPG exercise pairs
  produced duplicate resource names. Posters now use `-poster.jpg`; references
  and the generator match. The images and their licenses are unchanged.

## Verification before cloud builds

- All 80 mobile suites / 627 tests passed.
- Mobile TypeScript passed. Targeted lint passed for the consent changes.
- The 12 targeted backend consent/report tests passed.
- All 59 backend suites / 530 tests passed for the matching server source.
- Android production JavaScript export with Hermes and an asset map completed.
- The actual React Native resource-name helper confirms distinct names for all
  12 exercise GIF/poster assets.
- All 192 assets in the Android export map have no conflicting resource names
  across 204 resource destinations.
- Existing signing identities, package IDs and the production API URL are retained.

## Distribution

Version 1.5.0. EAS local auto-increment will advance Android code 31 and iOS build
27 to unused numbers. Google Play uses the existing production submission profile;
Apple's existing 1.5.0 draft is prepared for the new build after processing.

Store review and processing are separate from successful cloud compilation.
Physical camera, microphone and health-data smoke tests on the signed builds
have not been performed by this session. A blocking regression requires a new
build number and a forward fix; store binaries cannot be reverted with Git.

Build IDs, submission results and backend verification will be recorded after
the respective services confirm them. No private credentials belong in this file.
